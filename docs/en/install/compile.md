# Source Code Build

Before building from source code, complete the environment setup and source code download by referring to the project README. The process is not repeated here.

If your build environment has network access, refer to [Online Compilation](#online-compilation). The build script automatically downloads third-party software over the network. Otherwise, refer to [Offline Compilation](#offline-compilation) to manually download the third-party software.

After preparing the open source third-party software, you can choose from the following build methods as needed:

- **Custom operator package**:

  A package generated by compiling selected operators is called a custom operator package. It acts on the CANN package in **mount** mode without changing the content of the original package. The generated custom operator package has a higher priority than the original CANN package. This package supports aclnn and graph mode invocation of AI Core and AI CPU operators.

- **ops-ras package**:

  A package generated by compiling the entire project is called the ops-ras package. It can **completely replace** the corresponding part of the CANN package. This package supports aclnn and graph mode invocation of AI Core operators.

- **ops-ras static library**:

  > Description: If you need to **perform secondary distribution based on this project** and have **requirements on the software package size**, use static library compilation. This library can be linked with your application development program and only retains the operators required by the business, thereby achieving minimal software deployment.

  This means the entire project is compiled into a static library file, containing libcann_ras_static.a and aclnn interface header files. This package only supports aclnn invocation of AI Core operators.

## Online Compilation

If compiling in an environment with internet access, third-party dependencies are automatically installed during the compilation process. Manual installation is not required. The source code compilation and deployment commands for different scenarios are as follows:

### Custom Operator Package

1. **Compile the custom operator package**

    Enter the project root directory and execute the following compilation command:

    ```bash
    bash build.sh --pkg --soc=${soc_version} [--vendor_name=${vendor_name}] [--ops=${op_list}] [-j${n}]
    # Example: Compiling the AddExample operator
    # bash build.sh --pkg --soc=ascend910b --ops=add_example -j16
    # Compiling user operators in the experimental contribution directory (example with AddExample; use the actual contributed operator during compilation)
    # bash build.sh --pkg --experimental --soc=ascend910b --ops=add_example -j16
    ```

    - --soc: ${soc_version} indicates the NPU model. Use "ascend910b" (default) for Atlas A2 products, "ascend910_93" for Atlas A3 products, and "ascend950" for Ascend 950PR&950DT products.
    - --vendor_name (optional): ${vendor_name} indicates the name of the custom operator package to build. The default name is custom.
    - --ops (optional): ${op_list} indicates the operators to compile. If not specified, all operators are compiled by default. The format is "add_example,crypto,...", with multiple operators separated by commas ",".
    - --experimental (optional): Indicates that operators saved by users in the experimental contribution directory should be compiled.
    - -j (optional): Specifies the number of compilation threads to speed up compilation.

    If neither ${vendor_name} nor ${op_list} is specified, the ops-ras package is compiled. If you want to compile a custom operator package for all operators, specify ${vendor_name}. When the following message appears, the compilation is successful.

    ```bash
    Self-extractable archive "cann-ops-ras-${vendor_name}_linux-${arch}.run" successfully created.
    ```

    After successful compilation, the run package is stored in the build_out directory under the project root directory.

2. **Install the custom operator package**

    ```bash
    ./build_out/cann-ops-ras-${vendor_name}_linux-${arch}.run
    ```

    The default installation path for the custom operator package is `${ASCEND_HOME_PATH}/opp/vendors`. ${ASCEND_HOME_PATH} is configured through environment variables and indicates the installation path of the CANN toolkit package, generally ${install_path}/cann.

    > Description: You can configure the --install-path=${install_path} parameter to define the operator package installation directory. Before using the custom operator package, execute the source ${install_path}/vendors/${vendor_name}/bin/set_env.bash command. The set_env.bash script appends the custom operator package installation path to the environment variable ASCEND_CUSTOM_OPP_PATH, making the custom operator package effective in the current environment.

3. **(Optional) Uninstall the custom operator package.**

    After the custom operator package is installed, an `uninstall.sh` script is generated in the `${ASCEND_HOME_PATH}/opp/vendors/${vendor_name}_ras/scripts` directory. Use this script to uninstall the custom operator package with the following command:

    ```bash
    bash ${ASCEND_HOME_PATH}/opp/vendors/${vendor_name}_ras/scripts/uninstall.sh
    ```

### ops-ras Package

> **Description**: Full compilation builds all operators in the repository, which takes a long time depending on the machine configuration, `-j` parallelism, and whether third-party dependencies are downloaded over the network. For daily development, prioritize single-operator compilation (`--ops=<operator_name>`).

1. **Compile the ops-ras package**

    Enter the project root directory and execute the following compilation command:

    ```bash
    # Compile all operators except those in the experimental directory
    bash build.sh --pkg [--jit] --soc=${soc_version} [-j${n}]
    # Compile all operators in the experimental directory
    # bash build.sh --pkg --experimental [--jit] --soc=${soc_version} [-j${n}]
    ```

    - --soc: ${soc_version} indicates the NPU model. Use "ascend910b" (default) for Atlas A2 products, "ascend910_93" for Atlas A3 products, and "ascend950" for Ascend 950PR&950DT products.
    - --jit (optional): If set, indicates that operator binary files are not compiled. If you need to use aclnn to invoke operators, this option does not need to be set.
    - --experimental (optional): Indicates that operators saved by users in the experimental directory should be compiled.
    - -j (optional): Specifies the number of compilation threads to speed up compilation.

    When the following message appears, the compilation is successful.

    ```bash
    Self-extractable archive "cann-${soc_name}-ops-ras_${cann_version}_linux-${arch}.run" successfully created.
    ```

    ${soc_name} indicates the NPU model name, which is the content remaining after removing "ascend" from ${soc_version}. After successful compilation, the run package is stored in the build_out directory.

2. **Install the ops-ras package**

    ```bash
    # Installation command
    ./build_out/cann-${soc_name}-ops-ras_${cann_version}_linux-${arch}.run --full --install-path=${install_path}
    ```

    ${install_path}: Indicates the specified installation path. It must be installed in the same path as the toolkit package. The default installation path is `/usr/local/Ascend`.

3. **(Optional) Uninstall the ops-ras package**

    ```bash
    # Uninstall command
    ./${install_path}/cann/share/info/ops_ras/script/uninstall.sh
    ```

### ops-ras Static Library

> Description: The static library only supports Atlas A2 products and Atlas A3 products. The experimental operators do not currently support the use of static libraries.

1. **Compile the ops-ras static library**

    Enter the project root directory and execute the following compilation command:

    ```bash
    bash build.sh --pkg --static --soc=${soc_version} [-j${n}]
    ```

    - --soc: ${soc_version} indicates the NPU model. Use "ascend910b" (default) for Atlas A2 products and "ascend910_93" for Atlas A3 products.
    - -j (optional): Specifies the number of compilation threads to speed up compilation.
    When the following message appears, the compilation and compression are successful.

    ```bash
    [SUCCESS] Build static lib success!
    Successfully created compressed package: ${repo_path}/build_out/cann-${soc_name}-ops-ras-static_${cann_version}_linux-${arch}.tar.gz
    ```

    ${repo_path} indicates the project root directory, and ${soc_name} indicates the NPU model name, which is the content remaining after removing "ascend" from ${soc_version}. After successful compilation, the compressed package is stored in the build_out directory.

2. **Extract the ops-ras static library**

    Enter the build_out directory and execute the extraction command:

    ```bash
    tar -zxvf ./cann-${soc_name}-ops-ras-static_${cann_version}_linux-${arch}.tar.gz -C ${static_lib_path}
    ```

    ${static_lib_path} indicates the extraction path for the static library. The directory structure after extraction is as follows:

    ```text
    ├── cann-${soc_name}-ops-ras-static_${cann_version}_linux-${arch}
    │   ├── lib64
    │   │   ├── libcann_ras_static.a               # Static library file
    │   └── include
    |       ├── ...                                 # aclnn interface header files
    ```

## Offline Compilation

If compiling in an environment without internet access, prepare the dependent third-party software in advance, and then compile the source code. The specific process is as follows:

1. **Download third-party dependencies**

    Download the third-party software in advance in an environment with internet access. The following methods are currently available. Choose as needed:

    - Method 1: Download manually according to the table provided in [Third-Party Software Dependencies](#installing-third-party-dependencies). If downloading from other addresses, ensure that the version numbers are consistent.

2. **Compile the operator package**

    Upload the downloaded third-party software to the offline environment. You can store it in the `third_party` directory or a custom directory. **The former is recommended, as its compilation command is consistent with the command in the online compilation scenario.**

    - **third_party directory** (Recommended)

        Create a `third_party` directory in the project root directory (skip this step if it already exists) and copy the third-party software to this specified directory. The compilation command is the same as the online compilation command. For details, refer to [Online Compilation](#online-compilation).

    - **Custom directory**

        Create a `${cann_3rd_lib_path}` directory at any location in the offline environment, copy the third-party software to this directory, and ensure that the directory has the proper access permissions.

        ```bash
        mkdir -p ${cann_3rd_lib_path}
        ```

        In this case, the compilation command needs to additionally include `--cann_3rd_lib_path=${cann_3rd_lib_path}` based on the online compilation command to specify the path where the third-party software is stored. Assuming the storage path is `/path/cann_3rd_lib_path`, the corresponding commands for different compilation methods are as follows:

        - Custom operator package

            ```bash
            bash build.sh --pkg --soc=${soc_version} [--vendor_name=${vendor_name}] [--ops=${op_list}] --cann_3rd_lib_path=${cann_3rd_lib_path}
            # Example: Compiling the AddExample operator
            # bash build.sh --pkg --soc=ascend910b --ops=add_example -j16 --cann_3rd_lib_path=/path/cann_3rd_lib_path
            ```

        - ops-ras full package

            ```bash
            bash build.sh --pkg [--jit] --soc=${soc_version} --cann_3rd_lib_path=${cann_3rd_lib_path}
            # bash build.sh --pkg --soc=ascend910b --cann_3rd_lib_path=/path/cann_3rd_lib_path
            ```

        - ops-ras static library

            ```bash
            bash build.sh --pkg --static --soc=${soc_version} --cann_3rd_lib_path=${cann_3rd_lib_path}
            # bash build.sh --pkg --static --soc=ascend910b --cann_3rd_lib_path=/path/cann_3rd_lib_path
            ```

3. **Install/uninstall the operator package**

    The operator package results obtained from offline and online compilation are the same. They are stored by default in the build_out directory under the project root directory, and the installation and uninstallation commands are also the same. For details, refer to [Online Compilation](#online-compilation).

## Local Verification

After the source code package is deployed, you can execute UT cases through build.sh in the project root directory to verify whether the project functions are normal.

> Description: Executing UT cases depends on the googletest unit testing framework. For detailed information, see the [googletest official website](https://google.github.io/googletest/advanced.html#running-a-subset-of-the-tests).

```bash
# Install the test-related requirements.txt dependencies in the root directory
pip3 install -r tests/requirements.txt
# Method 1: Compile and execute UT test cases for specified operators and corresponding functions (choose one)
bash build.sh -u --[opapi|ophost|opkernel] --ops=add_example
# Method 2: Compile and execute all UT test cases
# bash build.sh -u
# Method 3: Compile all UT test cases without executing them
# bash build.sh -u --noexec
# Method 4: Compile and execute UT test cases for corresponding functions (choose one)
# bash build.sh -u --[opapi|ophost|opkernel]
# Method 5: Compile UT test cases for corresponding functions without executing them (choose one)
# bash build.sh -u --noexec --[opapi|ophost|opkernel]
# Method 6: Specify the soc when executing UT test cases
# bash build.sh -u --[opapi|ophost|opkernel] [--soc=${soc_version}]
```

Take verifying whether the ophost function is normal as an example. Execute the following command:

```bash
bash build.sh -u --ophost
```

After execution, the following content appears, indicating successful execution.

```bash
Global Environment TearDown
[==========] ${n} tests from ${m} test suites ran. (${x} ms total)
[  PASSED  ] ${n} tests.
[100%] Built target ras_op_host_ut
```

${n} indicates that n cases were executed, ${m} indicates m test suites, and ${x} indicates the time consumed to execute the cases, in milliseconds.

## FAQ

### Insufficient permission error when installing the custom run package

The default installation directory requires the current user to have read, write, and execute permissions. If a permission insufficient error is reported, choose one of the following methods:

- It is recommended to install to an absolute path writable by the current user and load the environment variable script generated by the package:

    ```bash
    ./build_out/cann-ops-ras-*linux*.run --install-path=/absolute/path/to/opp
    source /absolute/path/to/opp/vendors/custom_ras/bin/set_env.bash
    ```

- If you must install to the system CANN directory, use `sudo -E` to retain the currently configured CANN environment variables:

    ```bash
    sudo -E ./build_out/cann-ops-ras-*linux*.run
    ```
